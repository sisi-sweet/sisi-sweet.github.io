# 思思實驗室暫存區 🧪

這是思思實驗室的內容創作暫存區，所有由 Agent 生成的內容都會先儲存在這裡，等待用戶審核通過後才會部署到正式網站。

## ⚠️ 重要原則

1. **Agent 只讀不寫（對於 Hugo/Git）**：
   - Agent 只能寫入暫存區
   - Agent 不得直接寫入 Hugo content 目錄
   - Agent 不得執行 git 操作

2. **用戶完全控制部署**：
   - 只有用戶本人才能執行 git 操作
   - 用戶決定何時部署
   - 用戶有權拒絕任何不符合要求的內容

3. **審核通過才能部署**：
   - 未經用戶確認的內容不得上線
   - 用戶可多次要求修改
   - 用戶擁有最終決定權

## 🚀 完整工作流程

### 階段一：Agent 生成與儲存

1. Agent 接收用戶提供的產品連結
2. Agent 執行系統化分析（產品分析、競品分析、SEO 關鍵字策略）
3. Agent 生成完整內容套件（網站長文、多平台貼文）
4. ⚠️ Agent 將所有內容儲存至暫存區
5. Agent 完成後通知用戶內容已準備好，等待審核

### 階段二：用戶審核

1. 用戶開啟暫存區對應的資料夾
2. 瀏覽所有檔案內容，特別關鍵：
   - `04_網站長文.md`：這是最終要部署的文章
   - `01_產品分析報告.md`：檢查資訊準確性
   - `02_競品分析報告.md`：檢查競品資訊
3. 用戶可決定：
   - ✅ **通過**：進入部署階段
   - 🔄 **修改**：告知 Agent 需要調整的地方
   - ❌ **拒絕**：要求 Agent 重新分析

### 階段三：用戶手動部署

1. 用戶確認無誤後，手動執行以下操作：
   ```bash
   # 1. 複製文章到 Hugo content 目錄
   cp "staging/[產品資料夾]/04_網站長文.md" "sisi_lab/content/[類別]/[日期]_[產品名稱].md"
   
   # 2. （如有圖片）複製圖片到 static 目錄
   mkdir -p "sisi_lab/static/images/[年]/[月]/"
   cp "staging/[產品資料夾]/*.jpg" "sisi_lab/static/images/[年]/[月]/"
   
   # 3. 本地測試
   cd sisi_lab
   hugo server -D
   
   # 4. 測試無誤後
   git add .
   git commit -m "新增文章：[產品名稱]"
   git push
   
   # 5. 部署到 GitHub Pages
   ```

## 📋 暫存區檔案說明

### 01_產品分析報告.md
包含產品的深度分析資訊：
- 產品基本資訊
- 目標受眾分析
- 產品優劣勢分析

### 02_競品分析報告.md
包含競品分析資訊：
- 競品列表
- 競品對比表格
- 市場定位分析
- 競品內容分析

### 03_SEO關鍵字策略.md
包含 SEO 關鍵字策略：
- 核心關鍵字候選
- 關鍵字競爭度分析
- 內容切入點策略

### 04_網站長文.md ⭐
這是最終要部署的文章，包含：
- 完整的 frontmatter
- 文章內容（思思風格）
- SEO 優化標籤

### 05-07 多平台貼文
分別為 Facebook、Instagram、Threads 的貼文內容。

### 08_Hugo部署報告.md
包含部署資訊：
- 目標路徑
- 檔名建議
- 圖片處理說明
- 部署檢核清單

### 09_執行總結.md
包含執行總結：
- 使用的核心關鍵字
- 主要切入點
- 建議發布時間
- 預期效果

## 🔍 暫存區檔案狀態標記

- `⏳ 待審核`：Agent 剛生成，等待用戶審核
- `✅ 已確認`：用戶驗證過，可部署
- `❌ 已拒絕`：用戶不滿意，需重新生成

## 📝 注意事項

1. 暫存區是 Agent 生成內容的中轉站
2. 只有經過用戶審核通過的內容才能從暫存區移動到正式資料夾
3. 這樣確保了內容品質和用戶對內容的完全掌控
